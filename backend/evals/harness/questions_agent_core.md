# Agent 核心能力测试问题（不含低效空间）

用于人工评测或 LLM-as-judge：看 Agent 是否选对工具、参数是否合理、能否澄清、结果是否可用。  
不覆盖城市低效空间 Skill。

评分建议（每题 0–2 分）：

- 0：工具错/空跑/编造数据
- 1：方向对但缺关键步骤、跳过确认或参数不当
- 2：工具链正确、约束被尊重、结果可用、中文说明清楚

复杂度设计原则：含糊意图、多步依赖、数据源分流陷阱、缺参只问一个问题、失败可恢复。

---

## A. 数据发现与加载

1. **模糊表名 + 约束过滤**  
   问：数据库里有没有名字里带 park 或 公园 的空间表？先列出来，不要直接加载全部。  
   期望：`list_postgis_layers`，结果中按关键词过滤/说明匹配项  
   不期望：编造表名；跳过 list 直接 `load_postgis_layer`；默认走 GeoServer

2. **不确定 schema 的加载**  
   问：帮我把 parks 相关的那张表上到地图；我不确定是 `public` 还是别的 schema，表名也可能带前缀。  
   期望：先 `list_postgis_layers` → 让用户确认候选 → 再 `load_postgis_layer`  
   检查：未猜中前不硬加载；确认后参数含正确 schema/table

3. **数据库 vs GeoServer 分流（带干扰词）**  
   问：我要查我们自己库里的空间数据表做分析，GeoServer 上那些 WMS 先别管。  
   期望：PostGIS 工具  
   不期望：`get_custom_geoserver_data`（即使提到了 WMS/GeoServer）

4. **GeoServer 条件检索**  
   问：从已配置 GeoServer 找和道路/road 相关的图层，优先 WFS；如果结果太多，用关键词收窄，不要无界拉全量。  
   期望：`get_custom_geoserver_data`（带过滤/搜索词）  
   不期望：把图层名当成 PostGIS `schema.table` 去 `load_postgis_layer`

5. **会话图层 vs 外网重搜**  
   前置：地图已有 2+ 图层。  
   问：先盘点当前会话里已有图层和来源，哪几个适合做缓冲分析？不要重新从网上搜一遍同名数据。  
   期望：`list_user_layers` 和/或 `search_metadata`  
   不期望：无故 `geocode_*` / 外网重拉已有数据

## B. 地理编码与 POI

6. **行政边界 + 用途约束**  
   问：把「杭州市」行政边界加到地图，后续要用它裁剪别的图层，所以只要边界面，不要一堆兴趣点。  
   期望：`geocode_nominatim`（boundary/关系级结果）  
   检查：上图为多边形/边界；未误用 overpass 拉 POI

7. **POI + 空间范围约束**  
   问：以人民广场为中心，找上海市中心约 2km 内的医院；结果太多就先摘要数量和分布，不要一次塞满地图。  
   期望：先定位中心（nominatim）→ `geocode_overpass`（hospital + 范围）  
   检查：有合理 bbox/around；有数量摘要；范围未扩到全市无界

8. **缺地点但带干扰需求**  
   问：帮我找中学，最好还能按办学类型分类统计，然后上图。  
   期望：先只问一个阻塞问题（在哪个城市/范围），暂缓统计与上图  
   不期望：全球盲搜；在未定位前调用属性/空间分析工具

## C. 属性与空间处理

9. **字段未知时的筛选**  
   前置：地图已有 `city_parks`，字段名未知。  
   问：筛出「比较大」的公园——面积大概大于 1 公顷；先确认面积字段叫什么，再筛选，并简要说明单位假设。  
   期望：`attribute_tool2`（list/describe fields → filter）  
   检查：未瞎猜字段名；对 hectare/㎡ 换算有说明；给出筛选结果摘要

10. **缓冲单位与命名**  
    前置：已有道路图层，显示名可能是中文「道路」而非 `roads`。  
    问：给当前道路图层做 200 米缓冲区，输出单独图层，别覆盖原路网；如果图层名不确定先确认。  
    期望：必要时先 `list_user_layers` → `geoprocess`(buffer)  
    检查：输出新图层；单位为米；未静默覆盖

11. **裁剪前校验相交**  
    前置：已有 `aoi` 与 `landuse`，二者可能不相交。  
    问：用研究范围裁剪土地利用；如果两者空间上对不上，不要硬跑出空结果假装成功，先告诉我问题。  
    期望：确认图层存在 → `geoprocess`(clip/intersect)  
    检查：空结果时解释原因；不编造要素

12. **属性 → 空间 → 再摘要（三步链）**  
    前置：已有地块图层，含类型字段。  
    问：先筛出类型为公园/绿地的地块，缓冲 50 米，再告诉我缓冲后大概覆盖面积或要素数。  
    期望：`attribute_tool2` → `geoprocess` → 结果摘要（可用 attribute/python，但主链不能跳过前两步）  
    不期望：只用 `run_python_analysis` 一条龙绕过专用工具

## D. 样式、计划与跨 Skill 组合

13. **样式 opt-in + 局部修改**  
    前置：地图有 `rivers` 与其它图层。  
    问：只把 rivers 改成蓝色、填充约 40% 透明，其它图层样式一律别动。  
    期望：`style_layers`  
    不期望：`apply_color_scheme` 全局改色；未要求时 autostyle

14. **计划模式：加载 → 筛选 → 缓冲 → 样式**  
    开启 plan_mode。  
    问：从数据库找到并加载公园相关表，筛面积>5000，缓冲 100 米，最后把结果图层做成绿色半透明；先出计划让我确认。  
    期望：先 `create_execution_plan`，确认前不执行业务工具  
    检查：步骤含 PostGIS → attribute → geoprocess → style；用户确认后再执行

15. **跨源组合（DB + 编码 + 空间）**  
    问：先定位「苏州工业园区」边界，再从数据库加载道路相关表，用边界裁剪道路，并统计裁剪后道路条数。  
    期望：`geocode_nominatim` + PostGIS list/load + `geoprocess` + 属性/计数摘要  
    检查：顺序合理；缺表时先 list/澄清，不编造道路数据

## E. 外部数据、冲突指令与负例

16. **OSINT + 地点消歧**  
    问：看下北京最近有没有火点；如果工具要 bbox 或时间范围而我没给全，只问一个最关键的缺参，别连续追问。  
    期望：`nasa_fire_data`（必要时一次澄清）  
    不期望：用 `geocode_overpass` 搜「火点」POI 冒充

17. **冲突指令：闲聊夹带工具词**  
    问：你是谁？顺便说说你们支持 PostGIS 和缓冲分析吗？现在先不要连库、也不要跑 geoprocess。  
    期望：中文介绍能力；**零**业务工具调用  
    不期望：因提到 PostGIS/缓冲而触发 list/load/geoprocess

18. **缺图层 + 模糊算子**  
    前置：地图无图层。  
    问：对当前选中图层做个「空间关系分析」（可能是相交或裁剪，你看着办）。  
    期望：说明无可用图层，只问一个必要问题（用哪两个图层/做什么算子）；不选工具硬跑  
    不期望：伪造相交结果

19. **失败恢复 + 候选推荐**  
    问：加载 `public.not_a_real_table`；如果失败，从数据库里找名字最接近 park/road 的候选表给我选，不要假装已经加载成功。  
    期望：`load_postgis_layer` 失败 → `list_postgis_layers` → 给出候选  
    检查：错误可读；有明确下一步；无虚假成功

20. **过度请求的收敛**  
    问：帮我把全世界的学校都找出来，做成缓冲区，再配色，再和天气数据叠一下。  
    期望：拒绝无界任务或收敛范围；只问一个关键澄清（国家/城市）；不要开始全球 overpass  
    不期望：连续调用 overpass/geoprocess/style/weather 空转

## 建议评测集组成

| 类别 | 题号 | 数量 | 主要考察点 |
|------|------|------|------------|
| 数据加载分流 | 1–5 | 5 | list→load、DB/GeoServer、会话复用 |
| 编码/POI | 6–8 | 3 | 边界 vs POI、范围约束、缺参澄清 |
| 属性/空间 | 9–12 | 4 | 字段探查、单位、空结果、多步链 |
| 样式/计划/跨源 | 13–15 | 3 | opt-in 样式、plan_mode、跨 Skill |
| 外部/冲突/负例 | 16–20 | 5 | OSINT、指令冲突、失败恢复、收敛 |

自动化 deterministic harness（路由/注册表/别名）见 `cases_agent_core.json`；本题库更适合端到端对话评测。
